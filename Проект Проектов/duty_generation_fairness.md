# P1 №14: Справедливость генерации дежурств

Источник истины: `backend/app/main.py`, функция `generate_duties` (`POST /api/duties/generate`).

## Алгоритм (без скрытых эвристик)

1. Берётся список сотрудников с ролью `support` и `is_active_for_duties == True`, порядок фиксирован: `order_by(User.id)`.

2. Для каждого `support_user_id` ведётся счётчик **уже назначенных слотов до `start_date`** (из БД), затем счётчики обновляются по мере заполнения диапазона `[start_date, end_date]`.

3. Для каждой пары `(день, слот)` в диапазоне:
   - если **не** `overwrite` и назначение уже есть — слот пропускается, счётчики корректируются согласно существующему назначению;
   - иначе выбирается пользователь с **минимальным** текущим счётчиком; при равенстве — **случайный** выбор среди кандидатов с этим минимумом (`random.SystemRandom().choice`).

4. Случайность: только выбор среди пользователей с одинаковым минимальным счётчиком; отдельной «модели» или ML нет.

## Ограничения

- Справедливость понимается как **выравнивание суммарного числа назначений** по пользователям; перекос возможен на границах диапазона и при `overwrite=false` с частично заполненным периодом.
- Утренние/вечерние слоты не различаются — одинаковая логика для всех `slot` от `0` до `SLOT_COUNT-1`.

## Воспроизведение

См. smoke `check_generation_fairness.py` (happy-path: после генерации разброс суммарных назначений по сотрудникам не больше 1 для полного перезаписанного диапазона при ≥2 активных support).
