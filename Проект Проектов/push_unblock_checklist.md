# P2 №10: Блокировка Push и чек-лист разблокировки

## Что обычно блокирует Push в браузере
- Пользователь нажал `Блокировать` в системном запросе уведомлений для сайта.
- Для сайта отключено разрешение `Уведомления` в настройках браузера.
- Включен режим `Тихие уведомления` (quiet UI), из-за чего запрос скрывается.
- Страница открыта не по `https` (или не `localhost` в dev), поэтому Push/Web Push недоступен.
- Сброшены/повреждены site data (cookie/storage/service worker), из-за чего нужна повторная подписка.
- Корпоративные политики ОС/браузера запрещают уведомления.

## Быстрая диагностика (для сотрудника)
1. Открыть сайт и проверить значок замка в адресной строке.
2. Убедиться, что для сайта разрешены `Уведомления`.
3. Проверить, что сайт открыт по `https` (в локальной разработке допускается `http://localhost`).
4. Обновить страницу и заново подтвердить разрешение, если браузер его запрашивает.
5. Если запрос не появляется, сбросить разрешения сайта и открыть страницу снова.

## Чек-лист разблокировки (Chrome/Edge)
1. Открыть сайт приложения.
2. Нажать на значок замка рядом с URL.
3. В `Настройки сайта` выставить `Уведомления -> Разрешить`.
4. Если ранее стояло `Блокировать`, сменить на `Разрешить` и перезагрузить страницу.
5. Если не помогло: удалить данные сайта (`Cookies и данные сайта`) и зайти снова.
6. Проверить системные настройки Windows: уведомления для браузера должны быть включены.

## Чек-лист разблокировки (Firefox)
1. Открыть сайт приложения.
2. Нажать на значок разрешений в адресной строке.
3. Для уведомлений убрать блокировку и установить `Разрешить`.
4. Перезагрузить страницу и заново подтвердить запрос уведомлений.

## Чек-лист для администратора/поддержки
- Проверить, что окружение открывается по `https` (prod/stage).
- Проверить, что сотрудник не в режиме `Do Not Disturb` на ОС.
- Проверить корпоративные политики браузера (GPO/MDM), не блокируют ли notifications.
- Дать сотруднику шаги из этого файла и зафиксировать результат.
- Если после чек-листа не работает, эскалировать в ИТ с указанием браузера, версии, URL и скриншота site permissions.

## Критерий готовности P2 №10
Причины блокировки задокументированы; операционный чек-лист разблокировки подготовлен и пригоден для передачи сотрудникам.
