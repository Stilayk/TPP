# Roadmap — ProjectTP

Актуальность: **2026-05-18**. Источники: корневой `TASKS.md`, `HANDOFF.md`, `README.md` в каталоге приложения.

## Продукт

**ProjectTP** — веб-приложение для графика дежурств, дневных отчётов с выгрузкой в Excel, админских операций с пользователями, делегирования прав администратора, запросов обмена дежурствами (в том числе с назначенными администраторами), опциональной интеграции с **n8n** и **Битрикс24**, генерации инструкции «выход сотрудника» с публичной страницей по токену и QR (**№33**). По дежурствам реализовано **предупреждение заранее** (**№32**: за 5 минут следующему дежурному + дублирование в общий чат при старте слота по настройкам).

Дополнительно к базовому функционалу (по состоянию на май 2026):

- **График:** таблица и **календарный** вид (неделя/месяц); автогенерация **без выходных** (**№35**) и **без официальных праздников РФ** (**№53**, `duty_rf_holidays`); сохранение с **пустыми слотами** (**№36**); **копирование периода** как шаблон на другой диапазон дат (**№54**, `POST /api/duties/copy-range`); **фильтры отображения** дня/недели/месяца без лишних запросов к API (**№55**, селектор «Показ»); **выгрузка периода в Excel** для рассылки (**№56**, `GET /api/duties/export-period`).
- **Админка:** не только роль `admin`, но и **гранулярные права** — график, отчёты, уведомления (**№41**); экран **мини-аналитики** по слотам и обменам (**№43**), расширение метрик (**№57**: помесячно, распределение, эвристика перегруза); утренние слоты **07:00–08:00** в аналитике считаются отдельно от обычных дежурств (**№75**).
- **Уведомления:** настройки в БД, выбор активного канала (`cron` / `n8n`), флаги режимов; **редактируемые шаблоны** текстов ЛС и чата (**№42**); **встроенный планировщик** в процессе backend (APScheduler: каждый час в **:55** и **:00** по `TZ`, см. `notification_scheduler.py`) с возможностью отключения через БД (`scheduler_enabled`); внешний cron по-прежнему допустим для тех же эндпоинтов.
- **Интерфейс:** обновлённый визуальный слой и токены (**№38**, **№44**–**№47**), вкладка **«Полезные ресурсы»** с карточками и поиском (**№39**, **№48**).
- **Эксплуатация и доработки (№58–№66):** инструкция «выход» по блокам, минимальный GitLab CI (`pytest`), readiness БД, лимит неудачных входов, политика Max-Age сессии, `:focus-visible`, дисциплина `?v=` статики — см. `README.md` и `TASKS.md`.

Стек: **FastAPI**, **PostgreSQL** (миграции **Alembic**), статический фронтенд в `ProjectTP/frontend/`, **Docker Compose** как целевой способ развёртывания. В репозитории есть **pytest**-тесты для части логики уведомлений и Битрикс (`ProjectTP/backend/tests/`).

## Риски и зависимости

- **Битрикс и n8n:** один сценарий — один исходящий канал или явное разделение аудиторий; при пустом `N8N_WEBHOOK_URL` цепочка n8n не шлёт события.
- **Встроенный планировщик и внешний cron:** оба могут вызывать те же dispatch-режимы — не включать дубли без осознанной настройки (`scheduler_enabled`, источник в настройках, расписание cron).
- **№33:** публичная ссылка по QR — риск утечки чувствительных строк до истечения TTL; согласовать с безопасностью.
- **№32** и **№6:** явно развести интервалы 2 мин и 5 мин и получателей.
- Согласование формулировок в UI с заказчиком (метки неактивных к дежурствам и т.п.).
