# Roadmap — ProjectTP

Актуальность: **2026-07-01**. Источники: корневой `TASKS.md`, `HANDOFF.md`, `ТЗ-по-проекту.md`, `README.md`.

## Продукт

**ProjectTP** — веб-приложение для графика дежурств, дневных отчётов с выгрузкой в Excel, админских операций с пользователями, делегирования прав, запросов обмена дежурствами, опциональной интеграции с **n8n** и **Битрикс24**, генерации инструкции «выход сотрудника» с публичной страницей по токену и QR (**№33**). По дежурствам реализовано **предупреждение заранее** (**№32**: за 5 минут + общий чат при старте слота по настройкам).

### Реализованный функционал (сводка)

- **График:** таблица и календарь (день/неделя/месяц); автогенерация без выходных (**№35**) и праздников РФ (**№53**); пустые слоты (**№36**); копирование периода (**№54**); фильтры «Показ» (**№55**); Excel за период (**№56**); **раздельная автогенерация утра и дня** (макс. 2+2, одна кнопка, флаг утренних слотов, 2026-06-08); ручное редактирование без лимитов; лента **«Недавняя активность»** (2026-05-21).
- **Админка:** роль `admin` + делегированные права график/отчёты/уведомления (**№41**); вкладка **«Админ»** только для `role=admin` (**№68**); аналитика с разделением утра/дня (**№57**, **№75**); журнал выдачи admin (**№23**).
- **Уведомления:** настройки в БД, шаблоны (**№42**), встроенный APScheduler **:55** / **:00** по `TZ`; runbook и dedup-документы.
- **Интерфейс:** дизайн-система (**№38**, **№44**–**№47**); «Полезные ресурсы» с поиском, категориями, избранным (**№39**, **№48**, **№74**, **№76**); dashboard-оболочка настроек (**№73**).
- **Битрикс:** график в чат, ЛС за 5 мин / старт, обмен и запрос замены (**№22**, **№71**, **№72**).
- **Эксплуатация (№58–№66):** блоки инструкции выхода, GitLab CI (`pytest`), readiness, лимит входа, Max-Age сессии, `:focus-visible`, дисциплина `?v=` статики.
- **Документация для пользователей:** [site-guide.md](site-guide.md) (2026-07-01).

Стек: **FastAPI**, **PostgreSQL** (Alembic), статический фронтенд, **Docker Compose**. Тесты: `ProjectTP/backend/tests/`.

## Риски и зависимости

- **Битрикс и n8n:** один сценарий — один канал или явное разделение аудиторий.
- **Планировщик и внешний cron:** не дублировать dispatch без настройки (`scheduler_enabled`, dedup).
- **Публичная ссылка инструкции (№33):** риск утечки пароля до TTL.
- **№32 и №6:** развести 2 мин и 5 мин по получателям.
- **In-memory лимит входа:** при нескольких воркерах учёт не общий.
