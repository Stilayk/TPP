# Приёмка на стенде: чеклист основных сценариев

Краткий перечень happy-path проверок после выката. Отметьте результат прогона в таблице в конце файла (или скопируйте таблицу в тикет / Confluence — главное, чтобы у команды был **один** согласованный артефакт).

**Перед прогоном зафиксируйте:** URL стенда, дата, версия образа/commit, роли тестовых УЗ (`support` / `admin`), включены ли Битрикс/n8n на этом стенде.

Связанные материалы: [deploy-rocky-linux.md](deploy-rocky-linux.md), уведомления — [notifications-runbook.md](notifications-runbook.md), [notifications-dedup.md](notifications-dedup.md).

---

## 1. Вход и сессия

| # | Сценарий | Ожидание |
|---|----------|----------|
| 1.1 | Открыть страницу входа | Форма логина отображается |
| 1.2 | Вход под `support` | Попадание в приложение, видны разделы по роли |
| 1.3 | Вход под `admin` | Доступ к админским разделам (при наличии прав) |
| 1.4 | Выход / повторный вход | Сессия не «ломает» интерфейс |

## 2. График дежурств

| # | Сценарий | Ожидание |
|---|----------|----------|
| 2.1 | Табличный вид: выбор периода / обновление | Данные слотов соответствуют API/ожиданиям |
| 2.2 | Календарь: переключение неделя/месяц (если доступно) | Слоты и подписи читаемы, без ошибок в консоли |
| 2.3 | Редактирование слота (права на правку) | Сохранение успешно, изменение видно после обновления |
| 2.4 | Блок «кто дежурит» / текущий слот (если есть на стенде) | Согласован с таблицей на текущее время МСК |

## 3. Отчёты

| # | Сценарий | Ожидание |
|---|----------|----------|
| 3.1 | Создание / просмотр отчёта за день (по процессу стенда) | Данные сохраняются, ошибок нет |
| 3.2 | Экспорт в Excel (если используется) | Файл скачивается, открывается |

## 4. Админ-операции

*Выполнять только на стенде, где это разрешено политикой.*

| # | Сценарий | Ожидание |
|---|----------|----------|
| 4.1 | Список сотрудников, просмотр полей | Таблица загружается |
| 4.2 | Изменение безопасного поля (например ФИО / контакт — по регламенту стенда) | PATCH/сохранение успешно |
| 4.3 | Права / роли (если настраиваются на стенде) | Изменение отражается при следующем входе |

## 5. Уведомления (только если на стенде настроены Битрикс и/или n8n)

Пометка **(опц.)** — пропустите строки, если `BITRIX_*` / `N8N_*` не заданы.

| # | Сценарий | Ожидание |
|---|----------|----------|
| 5.1 **(опц.)** | Тестовое ЛС из админки (`duty-test` или эквивалент в UI) | Сообщение доходит до тестового пользователя в Битрикс |
| 5.2 **(опц.)** | Ручной dispatch «за 5 мин» / «старт» с контрольным `at=` (см. [notifications-diagnostics.md](notifications-diagnostics.md)) | Ответ API `sent` согласован с настройками; дублей по регламенту [notifications-dedup.md](notifications-dedup.md) нет |
| 5.3 **(опц.)** | «График на день» в чат Битрикс (если используется) | Одно сообщение, текст совпадает с графиком в UI |

## 6. Обмен дежурствами (если включён сценарий на стенде)

| # | Сценарий | Ожидание |
|---|----------|----------|
| 6.1 | Создание запроса обмена | Карточка появляется у второй стороны / в списке |
| 6.2 | Принятие или отклонение | Статус обновляется, график согласован с действием |
