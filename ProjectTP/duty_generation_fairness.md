# P1 №14: Справедливость генерации дежурств

Источник истины: `backend/app/routers/duties.py`, эндпоинт `POST /api/duties/generate`.

## Кто участвует в автогенерации

- Роли **`support`** и **`admin`**, флаг **`is_active_for_duties == true`**.
- Учётная запись **изначального администратора** (`BOOTSTRAP_ADMIN_USERNAME` / `is_bootstrap_admin` в API) в **автогенерацию не входит** — её слоты можно задать только **вручную** (`POST /api/duties/batch`).

## Алгоритм (без скрытых эвристик)

1. Для каждого участника пула ведётся счётчик **уже назначенных слотов до `start_date`** (из БД), затем счётчики обновляются по мере заполнения диапазона `[start_date, end_date]`.

2. Для каждой пары `(день, слот)` в диапазоне:
   - если **не** `overwrite` и назначение уже есть — слот пропускается, глобальный счётчик корректируется по существующему назначению;
   - иначе сначала отбираются те, у кого в **этот календарный день** уже меньше **`MAX_DUTY_SLOTS_PER_USER_PER_DAY` (2)** слотов; если таких нет (не хватает людей на 11 слотов без третьих смен) — допускается пул **всех** участников автогенерации;
   - среди отобранных выбирается пользователь с **минимальным** глобальным счётчиком; при равенстве — **случайный** выбор (`random.SystemRandom().choice`).

3. Случайность: только выбор среди пользователей с одинаковым минимальным глобальным счётчиком; отдельной «модели» или ML нет.

## Ручное редактирование графика

- `POST /api/duties/batch`: после слияния с БД на выбранную дату **нельзя**, чтобы у одного пользователя было **больше 2** слотов (включая изначального админа, если его назначают вручную).

## Ограничения

- Справедливость — **выравнивание суммарного числа назначений** по участникам пула; перекос возможен на границах диапазона и при `overwrite=false` с частично заполненным периодом.
- При малом числе активных сотрудников **повторы в один день** (более 2 слотов одному лицу) возможны только когда у всех уже по 2 слота в этот день, а слоты ещё остаются.

## Воспроизведение

См. smoke `check_generation_fairness.py` (happy-path: разброс суммарных назначений по участникам пула без bootstrap не больше 1 для полного перезаписанного диапазона при ≥2 таких пользователях; на каждый день не более 2 слотов на одного).
