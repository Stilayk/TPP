# P1 №14: Справедливость генерации дежурств

Источник истины: `backend/app/routers/duties_live.py` → `app.duty_generation.run_generation`, эндпоинт `POST /api/duties/generate`.

## Кто участвует в автогенерации

### Обычные дежурства (09:00–17:00)

- Роли **`support`** и **`admin`**, флаг **`is_active_for_duties == true`**.
- Учётная запись **изначального администратора** (`BOOTSTRAP_ADMIN_USERNAME` / `is_bootstrap_admin` в API) в **автогенерацию не входит** — её слоты можно задать только **вручную** (`POST /api/duties/batch`).

### Утренние дежурства (07:00–08:00)

- Подмножество пула обычных дежурств: **`is_eligible_for_morning_duties == true`** (настраивается в админке).
- Пара 07:00+08:00 назначается одному человеку из этого пула.

## Алгоритм (без скрытых эвристик)

1. Для каждого участника ведутся **два** глобальных счётчика — утренних и обычных слотов до `start_date` (из БД), затем обновляются по мере заполнения диапазона `[start_date, end_date]`.

2. Для каждой пары `(день, слот)` в диапазоне:
   - **нерабочий день для автогенерации** — суббота, воскресенье **или** официальный праздник/перенос РФ (`holidays.Russia`, см. `duty_rf_holidays.py`): новые назначения **не создаются**; при `overwrite=false` существующие записи в БД на такие дни сохраняются (ветка «уже есть назначение»). Предпраздничные сокращённые дни считаются **рабочими** для почасовых слотов.
   - если **не** `overwrite` и назначение уже есть — слот пропускается, соответствующий глобальный счётчик корректируется по существующему назначению;
   - иначе выбор исполнителя по правилам в `duty_generation.py`:
     - **09:00** — фиксированный логин `user`;
     - **07:00+08:00** — один человек из пула утренних, лимит **2** утренних слота/день;
     - **10:00–17:00** (и 09:00 в счётчике обычных) — из полного пула, лимит **2** обычных слота/день;
     - утренний и обычный лимиты **независимы** (2 утро + 2 день допустимо);
     - приоритет равномерности по соответствующему глобальному счётчику, `random.SystemRandom` среди кандидатов с минимальным счётчиком.

3. Случайность: только выбор среди пользователей с одинаковым минимальным глобальным счётчиком в рамках допустимого пула; отдельной «модели» или ML нет.

## Ручное редактирование графика

- `POST /api/duties/batch`: в теле — **ровно по одному элементу на каждый слот** `0..SLOT_COUNT-1`; `user_id: null` очищает слот (пустая ячейка допустима).
- Лимиты слотов на человека в день **не действуют** при ручном сохранении и копировании периода — администратор может назначить любое число слотов.

## Ограничения

- Справедливость — **выравнивание суммарного числа назначений** по участникам пула отдельно для утра и для дня; перекос возможен на границах диапазона и при `overwrite=false` с частично заполненным периодом.
- Минимальный пул: **1** сотрудник с утренним доступом и **5** в общем пуле (для 9 обычных слотов при лимите 2/день) на каждый рабочий день.
