## Бэклог

### 17) PostgreSQL вместо SQLite и миграции (Alembic)
- **Приоритет:** P2
- **Статус:** В очереди
- **Описание:** Заменить SQLite на **PostgreSQL** как основную СУБД (строка подключения и секреты через переменные окружения, сервис Postgres в compose при необходимости). Ввести Alembic для версионирования схемы; убрать SQLite-специфичные обходы (`PRAGMA`, `sqlite_master`, ручные `ensure_*` при старте) в пользу миграций.
- **Критерий готовности:** Приложение работает с PostgreSQL; в репозитории есть история миграций Alembic; «чистая» установка поднимает БД с актуальной схемой; путь миграции данных со старого SQLite описан или автоматизирован по согласованию (если нужен перенос существующих инсталляций).
- **Зависимости:** Нет

### 18) Разбиение монолитного `main.py`
- **Приоритет:** P2
- **Статус:** В очереди
- **Описание:** Поэтапно вынести из `Проект Проектов/backend/app/main.py` модели, сессию/движок БД, схемы Pydantic и группы эндпоинтов в отдельные модули или пакеты (например `models`, `database`, `schemas`, `routers`, `services`) так, чтобы точка входа FastAPI оставалась компактной, а внешнее поведение API и контракты UI не изменились.
- **Критерий готовности:** Структура пакетов согласована и отражена в импортах; `main.py` существенно сокращён по объёму; smoke/happy-path по ключевым сценариям API проходит; дублирования логики нет.
- **Зависимости:** Задача 17 (опционально — чтобы не переносить вынесенные модели дважды при смене СУБД; при параллельной работе согласовать порядок с исполнителем)
