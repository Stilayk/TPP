# Конвенции записей в HANDOFF.md

Документ задаёт **схему шагов** в журнале `HANDOFF.md` для репозитория TPP. Нормы хранения журнала (append-only, без секретов, очередь при параллели) — в `Проект Проектов/subagent-orchestration-policy.md`, §5.1–5.2.

## Якорь ACTIVE

Одна строка в начале файла (раздел **## Якорь ACTIVE**), чтобы агенту не разбирать весь лог для понимания фокуса.

- **Формат:** `- **ACTIVE:** P2 №… — кратко; или «см. Следующий шаг» + уточнение.`
- **Обновление:** при смене текущей задачи или явном переключении фокуса — **можно** заменить только эту строку (без правки истории **Лог шагов**).
- Блоки **Текущий статус задачи** и **Следующий шаг** по-прежнему не переписывать без договорённости с пользователем (см. `CONTINUE_PROMPT.md`).

## Логический шаг и микрошаги

**Нужна запись в Лог шагов, если:** завершён осмысленный результат по задаче; создан/удалён значимый файл; изменилось поведение API/UI; зафиксирована ошибка или блокер; пользователь явно попросил зафиксировать; конец сессии с незавершённой работой — краткий статус.

**Можно не создавать отдельный шаг, если:** одна-две правки опечатки или форматирования без смены логики; промежуточные неудачные попытки внутри одного логического шага до успеха (достаточно итогового шага). Не злоупотреблять: серия мелких коммитов по одной задаче — лучше один сводный шаг в конце пакета изменений.

## Обязательные поля каждой записи

Каждое действие субагента фиксируется одной записью в **Лог шагов**, содержащей:

- **Задача** — что именно выполнялось.
- **Время** — дата и время выполнения.
- **Кто исполнил** — агент/роль.
- **Как исполнил** — кратко: подход, инструменты, ключевые шаги.

## Рекомендуемые дополнительные поля

- **Результат** — что получено.
- **Статус:** `success` / `error` / `partial`.
- **Следующий шаг** — кто и что делает далее.

## Новые файлы в репозитории

При создании в шаге новых файлов (отчёты, чек-листы, инструкции, шаблоны):

- В **том же шаге** в поле **Как исполнил** или **Результат** указать **относительный путь от корня репозитория** к каждому созданному файлу (например `Проект Проектов/push_unblock_checklist.md` или `CONTINUE_PROMPT.md` в корне).
- Если файл в корне репозитория — указать имя файла явно (не только «создан файл»).
- При необходимости продублировать путь в `TASKS.md` у задачи строкой **Артефакт:** (см. конвенцию в шапке `TASKS.md`).

## Шаблон одной записи (копирование)

```markdown
### Шаг N
- **Задача:** …
- **Время:** YYYY-MM-DD HH:MM (локальное)
- **Кто исполнил:** роль / модель
- **Как исполнил:** подход, инструменты, ключевые шаги
- **Результат:** … *(рекомендуется)*
- **Статус:** success | error | partial *(рекомендуется)*
- **Следующий шаг:** … *(рекомендуется)*
```
