## 1. Назначение и границы

### 1.1. Цель

Внутренний веб-портал команды техподдержки для:

- ведения **графика дежурств** (07:00–17:00 МСК, слоты по часам);
- заполнения **дневных отчётов** с выгрузкой в Excel;
- **администрирования** пользователей, прав, генерации графика и уведомлений;
- быстрого доступа к **полезным ресурсам** (ссылки на корпоративные сервисы);
- генерации **инструкции при выходе** нового сотрудника (текст, Word, QR, публичная ссылка с TTL).

### 1.2. Вне scope (на момент версии)

- Мобильное приложение, SSO/LDAP (только логин/пароль в приложении).
- PDF-выгрузка графика (реализован только Excel).
- Встроенное почасовое «кто дежурит сейчас» в Битрикс — настраивается **эксплуатацией** (cron/n8n), не зашито в код.
- Idempotency ключи для уведомлений — регламент в [ProjectTP/docs/notifications-dedup.md](ProjectTP/docs/notifications-dedup.md), технические предохранители минимальны.

## 2. Пользователи и права

### 2.1. Роли

| Роль | Описание |
|------|----------|
| `support` | Сотрудник техподдержки: свой график, отчёты, обмен дежурствами, настройки |
| `admin` | Полный доступ, вкладка **Админ**, управление пользователями и ролями |

Первый администратор создаётся из переменных `BOOTSTRAP_ADMIN_*` при пустой БД. Изначального администратора нельзя лишить прав admin; в системе всегда должен остаться ≥1 admin.

### 2.2. Делегированные права (без роли admin)

Флаги на пользователе `support`:

| Флаг | Доступ в UI |
|------|-------------|
| `can_manage_duties` | Редактирование и сохранение графика на вкладке «График», кнопка «Отправить график на сегодня в Битрикс» |
| `can_manage_reports` | Просмотр чужих отчётов, выбор сотрудника, «Экспорт в Excel» на вкладке «Отчёты» |
| `can_manage_notifications` | Нет отдельной вкладки; настройки уведомлений в UI — только внутри «Админ» (нужна роль admin) |

**Вкладка «Админ»** видна только при `role === "admin"` (задача №68). Подразделы «Генерация», «Уведомления», «Аналитика» — внутри этой вкладки. Делегированные права открывают элементы на «График»/«Отчёты»; автогенерация, аналитика и управление пользователями — через «Админ» или API.

### 2.3. Участие в дежурствах

- `is_active_for_duties` — участие в автогенерации и обменах (админ может отключить).
- `is_eligible_for_morning_duties` — допуск к утренним слотам 07:00–08:00 при автогенерации.
- `duty_leave_dates` — дни, когда сотрудник **не назначается** при автогенерации (календарь в UI). Учётная запись `user` (служебный слот 09:00) не может задавать отгулы.

## 3. Функциональные требования

### 3.1. Аутентификация и сессия

- Вход по логину и паролю; пароли — bcrypt-хеш в БД.
- Cookie `session`, Max-Age — `SESSION_MAX_AGE_SECONDS` (по умолчанию 14 суток).
- После **12** неудачных попыток с пары IP+логин за **15 минут** — HTTP **429**.
- `GET /api/me` — текущий пользователь и права.
- Поле `last_seen_at` обновляется при входе и активности (не чаще 1 раза в 5 минут); отображается в админке «Был в сети».

### 3.2. График дежурств

**Слоты:** 11 часовых интервалов **07:00–17:00** (Europe/Moscow). Слоты 07:00 и 08:00 — **утренние**.

**Просмотр (все авторизованные):**

- Блок «Сейчас дежурит» — текущий слот по МСК, автообновление.
- Виды: **день** (таблица), **неделя**, **месяц** (календарь).
- Фильтр отображения: все слоты / только мои (данные на сервере не меняются).
- Подсветка своих слотов.

**Редактирование** (`can_manage_duties` или admin):

- Назначение сотрудника на слот или пустой слот «—»; сохранение пакетом.
- Ручное назначение **без лимита** слотов на человека в день.
- Отправка графика на сегодня в Битрикс (общий чат).

**Автогенерация** (`POST /api/duties/generate`):

- Диапазон дат, опция перезаписи.
- Пропуск субботы, воскресенья и **официальных праздников РФ** (`holidays`).
- Лимиты на человека в периоде: **≤2 утренних** + **≤2 обычных** слота; утренние — только из пула с `is_eligible_for_morning_duties`.
- Алгоритм справедливого распределения — см. [ProjectTP/duty_generation_fairness.md](ProjectTP/duty_generation_fairness.md).
- Копирование периода (`POST /api/duties/copy-range`) — перенос шаблона на другой диапазон той же длины.
- Экспорт периода в Excel (`GET /api/duties/export-period`, до 120 дней).

**Обмен дежурствами:**

- Запрос обмена двух занятых слотов на одну дату; принятие/отклонение второй стороной.
- Уведомление адресату в Битрикс (при `bitrix_user_id` и вебхуке).
- Обмен с участниками с ролью admin — разрешён (№34).

**Запрос замены:**

- Кнопка на главной — личные сообщения в Битрикс **всем admin** с заполненным `bitrix_user_id`.

**Недавняя активность:**

- `GET /api/activity/recent` — лента обменов и связанных событий на вкладке «График».

### 3.3. Отчёты

- Дневной отчёт на сотрудника и дату: строки «Задача», «Результат», «Время (мин)».
- KPI: число записей, суммарные часы, статус, время обновления.
- Финализация → формирование Excel на сервере; скачивание файла.
- Support видит только свои отчёты; `can_manage_reports` — выбор сотрудника и экспорт всех за дату.
- История последних изменений (`GET /api/reports/recent`).

### 3.4. Полезные ресурсы

- Каталог карточек со ссылками (seed + миграции Alembic).
- Категории: коммуникации, администрирование, мониторинг, сервисы.
- Поиск и фильтр по категории на клиенте.
- Избранное и «Недавно открывали» — `localStorage` по `user.id` (без API).
- Админ редактирует видимость карточек по категориям.

### 3.5. Инструкция «выход сотрудника»

- Модальное окно: ФИО, логин, пароль, домен, выбор **блоков** текста.
- `POST /api/instruction/employee-exit` — сборка текста (`employee_exit_blocks.py`).
- Word (.docx), копирование, публичная ссылка + QR (`EE_INSTRUCTION_SHARE_TTL_SECONDS`, по умолчанию 7 суток).

### 3.6. Админ-панель (только `role=admin`)

| Подраздел | Содержание |
|-----------|------------|
| Аналитика | KPI обычных и утренних слотов отдельно, обмены, перегруз, помесячно |
| Генерация | Автогенерация, копирование, Excel |
| Уведомления | Планировщик, флаги, шаблоны, тест, график в Битрикс |
| Сотрудники | CRUD, пароли, Bitrix ID, роли, делегированные права, журнал admin |
| Ресурсы | Фильтры категорий для карточек |

Делегированные права не заменяют вкладку «Админ»: расширенные операции (автогенерация, аналитика, пользователи) доступны только admin в UI.

### 3.7. Уведомления о дежурствах

**Каналы:** Битрикс24 (основной), опционально n8n (`N8N_DUTY_WEBHOOK_ENABLED`).

**Режимы:**

- За **5 минут** до слота — личное сообщение дежурному (триггер **:55**).
- В **момент старта** — личное + сообщение в общий чат (триггер **:00**).
- Отдельно: n8n за **2 минуты** (№6), график на день в чат, запрос замены admin.

**Планировщик:** APScheduler в процессе backend (`:55`/`:00` по `TZ`); отключается `scheduler_enabled` в БД. Внешний cron допустим по [ProjectTP/docs/notifications-dedup.md](ProjectTP/docs/notifications-dedup.md).

Эталон времени — **Europe/Moscow** ([ProjectTP/docs/duty-time-moscow.md](ProjectTP/docs/duty-time-moscow.md)).

## 4. Нефункциональные требования

| Область | Требование |
|---------|------------|
| СУБД | PostgreSQL, миграции Alembic |
| API | FastAPI, REST, сессии Starlette |
| Фронтенд | Статический HTML/CSS/JS в `ProjectTP/frontend/` |
| Развёртывание | Docker Compose (nginx + backend + postgres) |
| Health | `GET /api/health`, `GET /api/ready` (проверка БД) |
| CI | GitLab: `backend-pytest` |
| Безопасность | bcrypt, лимит входа, HTTPS-only cookie в prod |
| Кэш статики | Query-string `?v=` при изменении `app.js`/`styles.css` |

## 6. Критерии приёмки (базовый набор)

Полный чеклист прогона: [ProjectTP/docs/staging-acceptance-checklist.md](ProjectTP/docs/staging-acceptance-checklist.md).

Минимум для релиза:

1. Вход/выход support и admin без ошибок.
2. График: просмотр день/неделя/месяц; редактирование с правами; «Сейчас дежурит» согласован с таблицей.
3. Автогенерация на период ≥3 рабочих дней — разные назначения по дням; выходные/праздники пропускаются.
4. Отчёт: создание строк, финализация, Excel.
5. Обмен дежурствами: создание → принятие → график обновлён.
6. При настроенном Битрикс: тестовое ЛС из админки без дублей по регламенту dedup.
